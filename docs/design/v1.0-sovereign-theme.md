# Sovereign Code v1.0 — "Terminal Emerald" Design Language

> Status: **canonical** (default theme as of v1.0 GA)
> Tokens: [`apps/desktop/src/renderer/styles/tokens.css`](../../apps/desktop/src/renderer/styles/tokens.css) → `[data-theme="sovereign"]`
> Distilled from a visual exploration round in Google Stitch
> (Cursor + Linear + Raycast lineage; **dark theme refinement**, not a rebrand)

This document is the source-of-truth for the v1.0 desktop UI. It captures
the design tokens, the page-level intent, and the rationale for the
choices made in the redesign pass. If a screen or component disagrees
with this file, the screen is wrong (or this file needs an update).

## 1. Why a new theme

Before v1.0 the desktop app shipped four exploratory themes: `sentry`,
`sanity`, `mistral`, `replicate`. None of them were committed to as the
GA voice. For v1.0 we needed:

1. **A confident default** so first-run users see one polished surface
   instead of a paint-chip showcase.
2. **A dark-first identity** because the audience (developers running
   local Ollama models against 18 backend services) lives in IDEs and
   terminals.
3. **Local-first as visual language**: surface "Running Locally",
   "18 Services Online", "Local Node" as first-class chrome — not
   buried in a settings panel.

`sovereign` is that default. The legacy themes remain selectable via
Settings → Appearance for users who already have a preference; new
installs land on `sovereign`.

## 2. Design tokens

### Colors

| Token | Value | Use |
|-------|-------|-----|
| `--color-bg-base` | `#0D0D0D` | Page canvas |
| `--color-bg-deeper` | `#080808` | Status bar, modal scrim |
| `--color-bg-surface-1` | `#111111` | Sidebar |
| `--color-bg-surface-2` | `#141414` | Cards, dropdowns |
| `--color-bg-surface-3` | `#1A1A1A` | Input fields |
| `--color-bg-elevated` | `#1F1F1F` | Hover state on cards |
| `--color-border-subtle` | `#1F1F1F` | Hairline dividers (never load-bearing) |
| `--color-border-default` | `#2A2A2A` | Card outlines, focused inputs |
| `--color-border-strong` | `#404040` | Selection rings |
| `--color-text-primary` | `#F5F5F5` | Body, headings |
| `--color-text-secondary` | `#A3A3A3` | Captions, secondary labels |
| `--color-text-muted` | `#6B6B6B` | Meta (timestamps, tokens/s) |
| `--color-text-code` | `#6EE7B7` | Inline code, keywords |
| `--color-accent-400` | `#34D399` | Hover state of accent |
| `--color-accent-500` | `#10B981` | **Terminal Emerald** — active nav, primary CTA, AI status |
| `--color-accent-600` | `#059669` | Pressed state of accent |
| `--color-yellow-400` | `#F59E0B` | Warning badges (PR Review counter, training running) |
| `--color-red-400` | `#F43F5E` | Error states, destructive actions |

Emerald is the **only** non-monochrome color in the chrome. Reserve it
for: active nav item, send button, AI activity indicator, code-block
keywords. If you're tempted to use it for decoration, use
`--color-text-secondary` instead.

### Typography

| Family | Use |
|--------|-----|
| **Inter** | All UI text. 14px body, 13px caption, 11px meta. Letter-spacing -0.005em. cv02/cv03/cv04/cv11 alt-forms on for that "Linear" feel. |
| **JetBrains Mono** | All code, terminal output, latency/token meta, the tool-trace pill summary line. Ligatures off (calt 0, liga 0) — easier to read in diffs. |

### Spacing & radius

| Token | Value | Use |
|-------|-------|-----|
| `--radius-sm` | `4px` | Chips, badges |
| `--radius-md` | `6px` | Buttons, inputs |
| `--radius-lg` | `8px` | Cards, dropdowns |
| `--radius-xl` | `12px` | Modals, sheets |

Spacing follows Tailwind's 4px scale; no custom spacing tokens. Generous
whitespace — Cursor / Linear density, not GitHub density.

### Motion

* **Hover transitions**: `120ms ease-out` on background-color, border, and text color.
* **State transitions** (open/close, expand/collapse): `200ms ease-out`.
* **Streaming cursors and activity indicators**: subtle pulse, never spin
  outside of explicit load states.

## 3. Page-level intent

The redesign is **systemic, not surface-level**. The same components
re-skin every screen because they all consume the same tokens. Pages
that needed deeper changes:

### Chat (✅ in v1.0 PR)

* Inline **ToolTracePill** between user message and assistant response,
  collapsed by default as a 32px hairline pill: `→ Used 3 tools: grep ·
  read_file · write_file (1.2s)`. Mono caption, hairline `#1F1F1F`
  border. Click expands to per-tool rows with status badges.
* Top bar shows the conversation title (editable), Auto (CAMR) model
  picker, and a 3-icon utility tray (search · history · settings).
* Composer left rail: attach + slash-command picker. Right rail: voice
  mic + emerald send button. Cmd/Ctrl+Enter sends.

### Sidebar (✅ in v1.0 PR)

The existing 25-item nav rail keeps its structure; the visual change
is mechanical: active item gets a left emerald border + `bg-accent-500/15`
fill + `text-accent-400` foreground. Hover state lifts to `bg-bg-surface-2`.
Workspace identity ("Project Alpha · Local Context Active") pinned
above the nav.

### Status bar (✅ in v1.0 PR)

The existing StatusBar already surfaces model · GPU · tokens/s · training
· federation · voice. Under `sovereign` it just re-skins:
* The "Running Locally" badge inherits the new emerald-tinted token
  (`--color-local-badge-bg: rgba(16, 185, 129, 0.12)`,
  `--color-local-badge-fg: #34D399`).
* "● 18 Services Online" is rendered as the always-present right-aligned
  health summary (W6-T17 observability stack reports this).

### Other screens (📐 design tokens cover automatically)

Models / Training / Federation / Knowledge / Analytics / PR Review /
Orchestration / Settings — all already use `bg-bg-surface-*` and
`text-text-*` tokens. Flipping `data-theme="sovereign"` re-skins them
without touching their layout. Page-specific polish (e.g. Federation's
peer-graph map, Models' HF download cards) is tracked in the v1.0.1
follow-up.

## 4. Component checklist for new UI

When building a new screen or component, follow this checklist:

- [ ] Background uses `bg-bg-base` / `bg-bg-surface-{1,2,3}` / `bg-bg-elevated`. **Never** hardcode `#0D0D0D`.
- [ ] Borders use `border-border-subtle` for hairlines, `border-border-default` for outlines. **Never** hardcode `#1F1F1F`.
- [ ] Text uses `text-text-primary` / `text-text-secondary` / `text-text-muted`. **Never** hardcode `#F5F5F5`.
- [ ] Accent is `text-accent-400` / `bg-accent-500` only for: active nav item, primary CTA, AI status, code keywords. If you want decorative color, use `text-text-secondary`.
- [ ] Mono text (latency, tokens/s, command output) uses Tailwind `font-mono` (resolves to JetBrains Mono under `sovereign`).
- [ ] Hover states use `120ms ease-out` transitions. Open/close states use `200ms ease-out`.
- [ ] Status bar segment count never exceeds 8; truncate or drop low-priority segments first.

## 5. Future work (deferred to v1.0.1+)

* **Density toggle** — `Comfortable` / `Compact` user setting that swaps
  Tailwind's 4px scale for 3px. Currently fixed at Comfortable.
* **Tool trace expanded preview** — show streaming output diff inline
  rather than just the static args preview.
* **First-run theme picker** — onboarding step that previews the four
  legacy themes alongside `sovereign` so new users can opt out if they
  hate dark mode. (For now the toggle is buried in Settings.)
* **Federation peer-graph visualization** — Stitch sketched a beautiful
  globe + active-peers panel; not yet implemented in the React tree.
  Tracked separately.

## 6. Provenance

The visual exploration was done in Google Stitch on 2026-05-12. Six
frames were generated covering Chat (v1 + v2 with tool trace) plus
exploratory takes on Federation / Analytics / Training / Knowledge /
Orchestration. We did not import Stitch's code; we extracted the design
language (palette, typography, density, component shape) and re-built
inside the existing Tailwind + Zustand architecture. The Stitch frames
remain available on the Google Stitch account for reference.
